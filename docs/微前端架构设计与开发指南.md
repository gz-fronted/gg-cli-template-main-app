# 主应用微前端开发指南

主应用使用 React Router 管理页面路由，通过 Garfish 加载子应用。子应用的挂载与清理由主应用运行时统一管理。

## 入口与配置

- `src/main.tsx`：调用 `initializeMicroApps()`，渲染主应用；热更新销毁时释放路由和微应用资源。
- `src/micro-apps/bootstrap.ts`：定义子应用，初始化 Garfish，订阅登录态变化。
- `src/components/MicroAppHost/index.tsx`：提供挂载容器、加载状态、失败提示和重试入口。
- `src/micro-apps/runtime.ts`：管理实例所有权、生命周期队列、容量和资源释放。
- `src/micro-apps/session.ts`：在退出登录或 HTTP 401 时，先清理会话和微应用，再跳转。

在对应环境文件中配置子应用入口：

```dotenv
VITE_MICRO_APP_REACT_ENTRY=http://localhost:3001
```

开发、测试、生产环境分别读取 `.env.development`、`.env.test`、`.env.production`。入口应指向可访问的子应用 HTML，子应用服务器需要允许主应用跨域获取资源。生产部署时替换示例域名，并配置主应用和子应用的路由回退。

## 新增子应用

1. 在 `src/micro-apps/bootstrap.ts` 中定义 `MicroAppDefinition`，包含 `name`、`entry` 和 `basename`。
2. 在 `src/router/index.tsx` 中为对应的 `basename/*` 配置 `<MicroAppHost definition={应用定义} />`。
3. 按需配置菜单和环境变量，并在 `src/vite-env.d.ts` 补充变量类型。

`name` 应与子应用的 Garfish 构建配置一致，`basename` 应与主应用路由及子应用路由基准一致。应用定义应保持稳定引用，避免每次 React 渲染重新创建。

挂载由 `MicroAppHost` 负责；不要再为同一子应用配置 `activeWhen` 自动调度，也不要在页面中直接重复调用 `loadApp`。

## 生命周期与容量

运行时按 `name + basename + entry` 识别实例。同一实例只交给一个挂载容器，加载、显示、隐藏和清理通过队列串行执行。

关闭标签或淘汰标签时完整 `unmount`，重新打开时重新加载和挂载；切换路由时保留尚未关闭的标签。不保留空闲实例；卸载时清空容器引用和传入的登录态。卸载失败的实例继续占用容量。

`createMicroAppRuntime` 支持以下容量配置：

| 参数            | 默认值  | 含义                                     |
| --------------- | ------- | ---------------------------------------- |
| `maxTotalSlots` | `15`    | 活动、清理失败和底层加载中的总容量 |
| `loadTimeoutMs` | `30000` | 等待子应用加载的超时时间，单位毫秒       |

加载超时会结束等待，但不会取消 Garfish 的底层请求。底层请求返回前占用容量，晚到结果不会再挂载。清理失败的实例隔离保留，不会继续复用；清理其他实例仍会继续。

登录用户或 Token 变化时，运行时使旧会话任务失效并清理实例。不要绕过 `clearSessionAndNavigate` 直接实现退出登录，否则可能跳过必要的清理。

## 主子应用通信

每次 `mount` 前读取最新登录态，通过 `props.globalState` 传递：

- `user`：当前用户信息。
- `token`：当前登录 Token。
- `basename`：子应用路由基准。
- `contentOnly: true`：嵌入模式只显示内容区域，避免重复布局。

子应用应在其生命周期入口读取并同步这些值，避免把首次挂载的 Token 永久保存在闭包中。主应用和子应用默认分别打包各自依赖；模板没有启用 CDN 依赖共享。

## 子应用资源责任

主应用管理实例并不能代替子应用自身的资源清理。子应用必须提供 Garfish 生命周期，并在 `unmount` 时卸载 React 根节点，取消事件订阅、定时器、观察器和未完成的异步操作，释放图表、编辑器等外部实例。

子应用应在卸载时停止轮询、移除监听并释放订阅。全局资源必须有明确归属和释放入口。

## 故障恢复与诊断

排队、加载和挂载的整体等待默认上限为 30 秒。超时不取消底层操作，也不放开仍在执行的生命周期队列；运行时停止接受新挂载并提示刷新主应用。退出清理的等待同样有上限，避免登录导航一直等待。晚到挂载完成后仍会尝试完整卸载。

`getMicroAppDiagnostics()` 返回最多 200 条标量阶段记录，不保存 DOM、实例或认证信息。资源模块或 CSS 加载失败提供刷新入口；普通渲染错误保留重试。刷新会丢失未保存内容。

本轮未加入 dynamicCSS 依赖补丁。生产验收需覆盖反复开关、加载中退出、挂载阻塞、失败卸载及重新登录，另行确认 DOM 残留与内存趋势。

## 多标签与完整路由同步

`microAppDefinitions` 是子应用注册列表，驱动菜单和路由。每项的 name（同时作为 appId）与 basename 必须唯一，basename 使用不带末尾斜杠的绝对路径。当前仅配置 react 示例，可在列表中增加应用。

每个应用对应一个标签，保存完整 routePath（路径、query、hash）。打开已有应用的新链接时，路由和激活状态原子更新；仅 query 变化或清除 query 均会替换旧值。切换标签只切换宿主可见性，不 hide/show 或重新挂载；关闭标签完整卸载。标签数量与保活预算分离：最多保活 10 个最近访问的应用面板，超出时仅卸载最久未使用的面板，保留标签及完整 routePath；再次激活时重新挂载。标签显示顺序不随 LRU 变化。卸载会释放页面内存状态，不新增未保存内容保护，与 gz-zd-web 当前策略一致。标签不持久化，重新加载时从当前 URL 恢复，切换会话时清空。

初次挂载通过 props.globalState 的 appId、basename、routePath 传入路由。后续激活和路由更新通过 window CustomEvent `pilotcore:host-subapp-route` 通知，detail 为 `{ appId, appName, routePath }`。子应用应监听此事件更新自己的路由，卸载时移除监听。

当前模板 sandbox:false，子应用可以通过 `window.postMessage({ type: 'pilotcore:subapp-route-change', appId, routePath }, window.location.origin)` 回传路由。主应用只接受当前窗口、同源、活动应用的消息，不接受协议地址或以 // 开头的路径。不支持独立 iframe 来源的路由回传；如引入 iframe，需要单独注册并验证对应窗口来源。

验证覆盖：已有非活动标签的新链接、仅 query 更新、query 清除、关闭活动标签后的恢复、路由消息来源校验。生产子应用需遵守上述协议并联调。

## HostBridge 通用通信

`src/integration/host-bridge` 提供与 gz-zd-web 同名的协议事件和消息信封 `{ event, payload, appId, tabId, timestamp }`。当前一个应用一个标签，tabId 等于应用 name。主应用挂载子应用前注册目标，关闭、加载失败、会话切换时注销；旧注册的 cleanup 不会删除同标签的新目标。HMR 销毁时停止 bridge 监听并清理注册表。

默认接入事件：`g-user-logout`（等待统一会话清理后跳登录页，重复请求合并）、`g-navigate`（已注册应用，完整 routePath 加 params）、`g-close-tab`、`g-close-current-tab`、`g-navigation-consumed`（删除已消费 query 参数）。退出 redirectTo 只允许本地 /login 路径。CloseCurrentTab 当前只关闭来源标签，不实现 HF1 的 next 导航参数。

子应用可使用 `window.postMessage({ event: 'g-user-logout', appId, tabId }, window.location.origin)`，或同名 CustomEvent，其 detail 使用完整消息信封。接收端校验已注册目标、窗口来源和 origin。sandbox:false 的子应用共享主窗口，appId/tabId 是协作标识，不构成同窗口脚本间的安全隔离。

主应用可用 `hostBridge.on()` 注册扩展处理器，返回值必须在销毁时调用。`emitToTab()` 向已注册目标投递，禁止通配 origin。协议类型保留主题、遮罩、认证和活动标签事件名，但模板尚未实现这些事件的默认业务处理器，也不会自动广播 token。iframe 虽有目标类型定义，本轮没有实现 iframe 宿主接入。

## 截图差异范围核对

- 旧 cleanup 保护、子应用退出登录：本轮已同步。
- 完整加载诊断：应适配同步。现有阶段标量记录仍未具备完整 attemptId、阶段耗时、子应用阶段上报与资源信息链路。
- 多标签保活、LRU：应统一行为。已将标签与保活预算分离，最多 10 个面板按 LRU 保活，淘汰仅卸载面板，标签和完整路由保留。未保存内容保护未实现，与 gz-zd-web 当前策略一致。
- 测试、mock、内存采样：应迁入可复用测试场景和通用工具，业务专属 mock 与历史采样结果不直接复制。当前单测不能替代模板真实依赖构建、子应用联调和生产内存验收。
