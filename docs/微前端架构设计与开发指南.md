# 主应用微前端开发指南

主应用使用 React Router 管理页面路由，通过 Garfish 加载子应用。子应用的挂载、复用与清理由主应用运行时统一管理。

## 入口与配置

- `src/main.tsx`：调用 `initializeMicroApps()`，渲染主应用；热更新销毁时释放路由和微应用资源。
- `src/micro-apps/bootstrap.ts`：定义子应用，初始化 Garfish，订阅登录态变化。
- `src/components/MicroAppHost/index.tsx`：提供挂载容器、加载状态、失败提示和重试入口。
- `src/micro-apps/runtime.ts`：管理实例所有权、生命周期队列、容量和资源释放。
- `src/micro-apps/session.ts`：在退出登录或 HTTP 401 时，先清理会话和微应用，再跳转。

在对应环境文件中配置子应用入口：

```dotenv
VITE_MICRO_APP_REACT_ENTRY=http://localhost:3001
```

开发、测试、生产环境分别读取 `.env.development`、`.env.test`、`.env.production`。入口应指向可访问的子应用 HTML，子应用服务器需要允许主应用跨域获取资源。生产部署时替换示例域名，并配置主应用和子应用的路由回退。

## 新增子应用

1. 在 `src/micro-apps/bootstrap.ts` 中定义 `MicroAppDefinition`，包含 `name`、`entry` 和 `basename`。
2. 在 `src/router/index.tsx` 中为对应的 `basename/*` 配置 `<MicroAppHost definition={应用定义} />`。
3. 按需配置菜单和环境变量，并在 `src/vite-env.d.ts` 补充变量类型。

`name` 应与子应用的 Garfish 构建配置一致，`basename` 应与主应用路由及子应用路由基准一致。应用定义应保持稳定引用，避免每次 React 渲染重新创建。

挂载由 `MicroAppHost` 负责；不要再为同一子应用配置 `activeWhen` 自动调度，也不要在页面中直接重复调用 `loadApp`。

## 生命周期与容量

运行时按 `name + basename + entry` 识别实例。同一实例只交给一个挂载容器，加载、显示、隐藏和清理通过队列串行执行。

离开路由时调用 `hide`，再次进入时优先调用 `show`，避免重复执行入口。停靠后清空旧容器引用和传入的登录态。空闲实例按停靠顺序回收，活动实例不会因空闲池超限而被卸载。

`createMicroAppRuntime` 支持以下容量配置：

| 参数            | 默认值  | 含义                                     |
| --------------- | ------- | ---------------------------------------- |
| `maxIdleSlots`  | `5`     | 最多保留的空闲实例数                     |
| `maxTotalSlots` | `15`    | 活动、空闲、清理失败和底层加载中的总容量 |
| `loadTimeoutMs` | `30000` | 等待子应用加载的超时时间，单位毫秒       |

加载超时会结束等待，但不会取消 Garfish 的底层请求。底层请求返回前占用容量，晚到结果不会再挂载。清理失败的实例隔离保留，不会继续复用；清理其他实例仍会继续。

登录用户或 Token 变化时，运行时使旧会话任务失效并清理实例。不要绕过 `clearSessionAndNavigate` 直接实现退出登录，否则可能跳过必要的清理。

## 主子应用通信

每次 `mount` 或 `show` 前读取最新登录态，通过 `props.globalState` 传递：

- `user`：当前用户信息。
- `token`：当前登录 Token。
- `basename`：子应用路由基准。
- `contentOnly: true`：嵌入模式只显示内容区域，避免重复布局。

子应用应在其生命周期入口读取并同步这些值，避免把首次挂载的 Token 永久保存在闭包中。主应用和子应用默认分别打包各自依赖；模板没有启用 CDN 依赖共享。

## 子应用资源责任

主应用管理实例并不能代替子应用自身的资源清理。子应用必须提供 Garfish 生命周期，并在 `unmount` 时卸载 React 根节点，取消事件订阅、定时器、观察器和未完成的异步操作，释放图表、编辑器等外部实例。

子应用采用 `hide/show` 复用时，应按业务需要在隐藏阶段暂停轮询等后台任务，在显示阶段恢复。全局资源必须有明确归属和释放入口。
